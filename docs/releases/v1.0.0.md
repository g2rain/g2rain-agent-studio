# v1.0.0｜GHCR 首次镜像发布

## 组件与平台边界

G2rain（谷雨）是面向企业的开源智能体平台，将 SaaS 基座、知识库、智能体与业务应用组织在同一体系中。智能体平台和智能客服已开发完成并开源；交易、订阅、计量计费等商业化能力仍处于规划设计。

本仓的 Agent Studio 只是 Agent 配置和资料领域服务：维护 Agent 画像、Skill 定义与执行契约、Agent-Skill 及 Skill-Tool 绑定，并向 Agent Runtime 提供目录、画像和能力包。它不执行对话或任务，不注册 MCP 服务或工具，不管理模型供应商，也不替代 Gateway、IAM、部署编排或整个 G2rain 平台。

## 构建与运行事实

- 项目版本事实源：根 `pom.xml` 的 `<revision>`，本次为 `1.0.0`；根 POM 使用 Spring Boot `4.1.2`，Java release `25`，Spring Cloud `2025.1.4`，Jib Maven Plugin `3.5.2`。
- 构建/测试：`mvn clean verify`。本地镜像脚本 `./build.sh <tag>` 会先执行 `mvn clean install`，然后用 Jib 写入本地 Docker daemon。
- 容器：Startup 模块的 Jib 配置使用 `eclipse-temurin:25.0.4.1_1-jre`，入口类为 `com.g2rain.agent.studio.Application`，声明端口为 `8080`；默认 profile 是 `nacos`，端口可由 `SERVER_PORT` 覆盖。
- 运行依赖：JDK 25/Maven 用于构建；服务运行时需要 Nacos、MySQL、Redis，并应通过 Gateway/IAM 与 Runtime 集成。

本地构建、CI 构建与测试、容器构建、GHCR 推送、匿名拉取、在线演示和实际部署验证是不同活动：本工作流只完成 CI 构建/测试及镜像推送；G2rain 的在线演示不表示本组件已独立部署验证。

## GHCR 交付

镜像地址为 `ghcr.io/g2rain/g2rain-agent-studio`。稳定 `v1.0.0` tag 在 `main` 历史中、发布说明存在且版本与根 POM 匹配时，CI 构建并推送：

- `ghcr.io/g2rain/g2rain-agent-studio:1.0.0`
- `ghcr.io/g2rain/g2rain-agent-studio:sha-<完整提交SHA>`

不发布 `latest`。先推送版本 tag 和 SHA tag；只有二者均成功，Actions Summary 才宣布发布成功。工作流不会创建 GitHub Release、部署服务或变更包可见性。

镜像 OCI 元数据为：`org.opencontainers.image.source=https://github.com/g2rain/g2rain-agent-studio`、`org.opencontainers.image.licenses=Apache-2.0`、title `g2rain-agent-studio` 和 Maven 项目 version。许可证与仓库 `LICENSE` 一致。

## 镜像内容与安全

按 Startup 模块的 Maven resources 配置和 Jib 的 Spring Boot 容器化机制，运行层由应用依赖、类和 `src/main/resources` 编译后的资源组成；它不是 Dockerfile 上下文，也不受 `.dockerignore` 管理。本项目没有 Dockerfile 或 `.dockerignore`。已跟踪的 `g2rain-agent-studio-startup/src/main/resources/application-dev.yml` 和 `application-nacos.yml` 因而是预期会进入应用的路径，其中含默认 Nacos 账户/密码配置，属于镜像内可读的敏感默认值风险。请在生产以 Secret、环境变量或受控 Nacos 配置显式覆盖凭据并按组织流程轮换；不要把生产密钥、Token 或私有地址写入仓库、镜像或命令行。由于本次本地构建未通过且 Docker daemon 不可用，尚未对最终镜像层做实际检查。

## 发布顺序与权限

1. 将发布改动、此说明和工作流合入 `main`，并在该已验证提交创建 `v1.0.0` tag。
2. 等待 Actions 完整执行 `mvn clean verify` 和 Jib 双 tag 推送。
3. 首次成功后，到 GitHub Packages 的 **Package settings → Change visibility → Public** 设为 Public；如组织管理员禁止操作，联系管理员。
4. 如现有 GHCR 包返回 `denied`，检查 **Package settings → Actions access** 是否授予本仓写权限，再检查组织 Packages 策略；不要仅凭工作流的 `packages: write` 假定可推送。
