# g2rain-agent-studio 缺点与劣势

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-22 |
| 来源 | 2026-11-22 审查对话中的评估与讨论 |
| 范围说明 | 本项目**没有做逐行审计**，只读了总体结构、README 与向 Runtime 提供能力包的 `AgentProfileServiceImpl`（目录、画像、技能摘要、能力包）。以下是从 Runtime 与本体的审查中看到的、与 Studio 相关的缺点 |

## 一、劣势

### 1.1 没有单元测试

`src/test` 下没有测试类。Studio 是 Agent、Skill、执行契约、工具绑定的权威数据源，Runtime 每一轮都依赖它返回的能力包，建议至少给能力包组装（`selectCapabilityBundle`）、可见性（平台与自定义资源的合并）、启停过滤补上测试。

### 1.2 契约编写缺少辅助

- Runtime 的既定立场是不在装载时校验契约，配置是否正确由配置者负责；Studio 是唯一能在配置阶段帮助作者的地方。
- 本次未核实 Studio 保存技能时是否会校验契约。可以考虑在 Studio 里提供“契约体检”：只给出提示、不拦截保存，与 Runtime 的立场不冲突。
- Studio 是开源项目，不能依赖闭源的本体，契约体检只能覆盖契约模式。

### 1.3 Runtime 每轮都拉取能力包

Runtime 每轮都会请求能力包，没有缓存。Studio 一旦不可用，续跑中的任务就会出现审计中所说的“技能缺失后空跑”（Runtime 审计 P1-5）。Studio 的可用性因此直接影响对话的正确性，建议：

- 在 Runtime 侧区分“调用失败”与“确实为空”（随 Runtime 修复一起做）；
- 评估是否对能力包按 `agentId + 版本` 做短时缓存，以降低对 Studio 的依赖和每轮的延迟。

## 二、待办

如需商用评估，Studio 还需要做一轮逐行审计（约 5 千行手写代码），重点是租户可见性（`WithoutIsolation` 的使用）与生成接口的暴露面。
